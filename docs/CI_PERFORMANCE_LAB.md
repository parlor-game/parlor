# Production CI performance lab

Target 20–30 minutes wall time, including runner queues. Production retains all three Apple Release architectures, both Apple gate joins, the Android package gate, 38 managed tests, 12 restart journeys, and source-bound evidence and cleanup. Native development can use targeted Debug tasks. Only real optimized Release links qualify Release performance.

## Evidence

- The first Production attempt at `30d57d7` measured **64m05s** for the ARM64 simulator Release wrapper job, **53m44s** for ARM64 device Release and **41m31s** for x64 simulator Release. Swift host acceptance started **17m05s** after the run started and then ran **36m06s**. Check the actual dependency graph before attributing any runner delay to a job dependency. [Production attempt 1](https://github.com/parlor-game/parlor/actions/runs/45940466368/attempts/1)
- Android installed runtime took **43m45s**. Its API 35 Release and API 34 Debug suites run serially, on separate supervised emulator lifecycles. The API 34 Debug app/test pair is also built by the parallel restart lane. A common/package-only retry took **24m25s** and passed. That partial rerun is no full-workflow baseline. [Runtime job](https://github.com/parlor-game/parlor/actions/runs/45940466368/job/140313351903) · [Targeted retry](https://github.com/parlor-game/parlor/actions/runs/45940466368/job/140333302922)
- The exact-source simulator `smallBinary` trial reported **54m36s** Gradle, **58m44s** build/test, and **61m59s** for the job. Native compiler **47m35s** included **25m02s** eliminating redundant initializer calls. The final linker itself was about **4 seconds**. The phase graph is nested, so adding all rows would double-count. The isolated initializer-phase experiment passed one cold launch but still took **47m37s** overall. [Size trial](https://github.com/parlor-game/parlor/actions/runs/45923612465/artifacts/15168290340) · [Initializer trial](https://github.com/parlor-game/parlor/actions/runs/45908708353)
- The repository uses Kotlin **2.4.10**, Gradle **8.13**, AGP **8.13.2**, JDK **21**, and qualified Xcode **26.3 (17C529)**. Gradle already enables parallelism, task caching and configuration caching. CI shares verified Gradle dependency downloads and wrapper distributions. Native compiler caches, task outputs and configuration graphs need separate hit measurements and trust decisions. The Swift-facing dynamic Compose framework has no Gradle `export` declarations or `transitiveExport` setting. The Native executable still links the Compose and game dependency closure.

## Running a comparison

Dispatch **Native link lab** on a reviewed `perf/*` branch with a distinct full baseline SHA from its ancestry. Select `plan` first. The candidate is the selected branch's exact triggering commit. Both roles run the same single simulator ARM64 Release link task on fresh standard ARM64 runners, using the same reviewed Xcode build and only the exact dependency cache key. `link` requires the real link, native phase timings and an ARM64 output. Both modes report provenance, the cache restore step window and hit status, Gradle wall time and task outcomes. Link mode adds the Gradle profile, compiler phases and framework checksum and size. The lab disables cross-build task output and configuration caches for the paired clean comparison. It does not execute XCTest.

Use Actions job/step timestamps for queue, Xcode/toolchain setup and upload/cleanup. Compare only matching toolchain/runner/cache-state pairs. A hit for only one role, a failed plan, or a skipped link disqualifies the pair as compiler evidence. Before qualifying a compiler change, run the Release wrapper and a cold-launch XCTest on the exact candidate, then validate the other two Release architectures. Promote only with meaningful observed savings and passing functional gates. Require a full protected PR and a separate full Production run after merge. Keep unrelated device or Store gates in place.
