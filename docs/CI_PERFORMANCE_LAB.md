# Production CI performance lab

Target 20–30 minutes wall time, including runner queues. Production retains all three Apple Release architectures, both Apple gate joins, the Android package gate, 38 managed tests, 12 restart journeys, and source-bound evidence and cleanup. Native development can use targeted Debug tasks. Only real optimized Release links qualify Release performance.

## Evidence

- The first Production attempt at `30d57d7` measured **64m05s** for the ARM64 simulator Release wrapper job, **53m44s** for ARM64 device Release and **41m31s** for x64 simulator Release. Swift host acceptance started **15m05s** after the run started and then ran **36m06s**. Check the actual dependency graph before attributing any runner delay to a job dependency. The API 34 Debug app/test pair is also built by the parallel restart lane. API 35 Release Gradle execution alone took 24m53s. The API 34 portion used 3m33s for Debug APK assembly, 1m31s for device setup, and 10m25s for the managed suite. A common/package-only retry took **24m25s** and passed. That partial rerun is no full-workflow baseline. - The exact-source simulator `smallBinary` trial reported **54m36s** Gradle, **58m44s** build/test, and **61m59s** for the job. Native compiler **47m35s** included **25m02s** eliminating redundant initializer calls. The final linker itself was about **4 seconds**. - The repository uses Kotlin **2.4.10**, Gradle **8.13**, AGP **8.13.2**, JDK **21**, and qualified Xcode **26.3 (17C529)**. ## Running a comparison

Dispatch **Native link lab** on a reviewed `perf/*` branch with a distinct full baseline SHA from its ancestry. Select `plan` first. The candidate is the branch's exact triggering commit. Both roles run the same simulator ARM64 Release target, sequentially on one ARM64 runner and verified Xcode build. This prevents a hosted-image rollout from invalidating two expensive links. Each role starts with an isolated checkout and its own Gradle and Kotlin/Native state. The same copy of the exact dependency-cache restore seeds both Gradle homes. Both modes report provenance, the restore window and hit status, Gradle wall time and task outcomes. Link mode additionally requires real optimized compilation and records Native phases, output architecture, checksum and size. The lab disables Gradle task output and configuration caches for paired measurements. Runtime acceptance is a separate job. [Gradle cache isolation](https://docs.gradle.org/current/userguide/dependency_caching.html) · [Kotlin/Native data directory](https://kotlinlang.org/docs/native-improving-compilation-time.html)

Checksum-verify the report artifact. It contains paired reports and `comparison.json`, reproducible with `python3 scripts/ci/native_link_lab.py compare BASELINE.json CANDIDATE.json`. Use Actions timestamps for queue, Xcode/toolchain setup and upload/cleanup. Treat a failed plan or skipped link as incomplete compiler evidence. Before qualifying a compiler change, run the Release wrapper and a cold-launch XCTest on the exact candidate, then validate the other two Release architectures. Promote only with measured savings and passing functional gates. Require a full protected PR and a separate full Production run after merge. Keep device and Store gates in place.

### Gradle task output relocation

Kotlin 2.4.10 marks its Native link task cacheable. Its ability to restore a Parlor framework across clean checkout paths remains a separate question from Kotlin/Native Release binary caching. `cache-probe` builds the exact reviewed baseline's Debug simulator framework once, then lets Gradle restore matching outputs in a separate checkout and Gradle home. It requires a real cache store and `FROM-CACHE` result for the same Native link key, plus identical ARM64 binary bytes and exact source trees. It measures both Gradle commands and the local transfer. The cache stays on the hosted lab runner. A successful Debug result only justifies a separate Release check and a fresh simulator launch of that verified output. Avoid sharing outputs with signed publishing workflows. [Pinned link task](https://github.com/JetBrains/kotlin/blob/v2.4.10/libraries/tools/kotlin-gradle-plugin/src/common/kotlin/org/jetbrains/kotlin/gradle/targets/native/tasks/KotlinNativeLink.kt) · [Gradle cache portability](https://docs.gradle.org/current/userguide/build_cache_debugging.html) · [Cache writer trust](https://docs.gradle.org/current/userguide/securing_build_tool.html)
